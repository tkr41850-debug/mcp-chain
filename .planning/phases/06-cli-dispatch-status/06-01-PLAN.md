<resolved_decisions>
The following decisions are LOCKED by 06-CONTEXT.md / 06-RESEARCH.md. Do NOT revisit during execution:

**LD-1 — Exit code contract (from CONTEXT.md §Exit code contract, locked; Phase 8 bash monitor depends on it):**

| Store result                                  | stdout           | stderr                                     | exit |
|-----------------------------------------------|------------------|--------------------------------------------|------|
| `record.Status == "resolved"`                 | `resolved\n`     | (empty)                                    | 0    |
| `record.Status == "pending"`                  | `pending\n`      | (empty)                                    | 2    |
| `errors.Is(err, store.ErrUnknownID)`          | (empty)          | `mcp-chain: unknown id: <id>\n`            | 1    |
| any other error (schema / corrupt / open-fail)| (empty)          | `mcp-chain: <err>\n`                       | 1    |

**LD-2 — Testability pattern:** Use `runStatus(out, errW io.Writer, path, id string) int` (pure function over writers + path), NOT a `StatusCmd.resolveStatus() int` method. Unit tests call it with `bytes.Buffer` pairs and `t.TempDir()` paths; `StatusCmd.Run` calls `os.Exit(runStatus(os.Stdout, os.Stderr, ..., c.ID))` for the 1/2 cases and `return nil` for the 0 case.

**LD-3 — `runStatus` is env-var pure:** `runStatus` MUST NOT call `statepath.Resolve()`. Resolution happens inside `StatusCmd.Run` so unit tests never touch `$XDG_STATE_HOME` / `$HOME`. (Pitfall 3.)

**LD-4 — Do NOT implement `ExitCoder` for the pending case.** Returning a kong `ExitCoder` error causes `FatalIfErrorf` to write `err.Error()` to stderr before exiting, violating the `—` stderr column of the pending row. Always use `os.Exit(code)` from `Run`. (Pitfall 2, RESEARCH §Anti-Patterns.)

**LD-5 — Manual `--version` pre-parse, drop `kong.VersionFlag`.** `VersionFlag.BeforeReset` hard-codes `app.Stdout`, which `kong.Writers(os.Stderr, os.Stderr)` repoints to stderr. The only clean fix is to scan `os.Args[1:]` for `--version` in `main` before `kong.Parse`, print `"mcp-chain " + version` to `os.Stdout`, and `os.Exit(0)`. Also drop the `kong.Vars{"version": ...}` call (no longer needed). (Pitfall 5.)

**LD-6 — Schema-version / corrupt-json errors fold into generic exit 1.** No distinct exit code for these; the default branch of the switch writes `fmt.Fprintf(errW, "mcp-chain: %v\n", err)` and returns 1. The operator sees the detail via the wrapped message. (CONTEXT §Non-goals.)

**LD-7 — 10-concurrent timing threshold: `< 1s`.** Matches SC #2 literal wording. If Windows CI flakes in Phase 9, Phase 9 may raise it with a citation; do NOT pre-relax here.

**LD-8 — No new flags on `status` in v1.** No `--format`, no `--wait`, no `--timeout`, no `--json`. Kong grammar for `StatusCmd` stays exactly `ID string `arg:"" help:"Id to check."``.

    ```go
    // Package cli: status subcommand (Phase 6).
    //
    // StatusCmd is the kong handler for `mcp-chain status <id>`.
    // runStatus is the exit-code decision tree extracted for
    // unit-testability via captured io.Writer pairs — no os.Exit,
    // no os.Stdout / os.Stderr references, no env-var reads.
    package cli

    import (
        "errors"
        "fmt"
        "io"
        "os"

        "github.com/tkr41850-debug/mcp-chain/internal/statepath"
        "github.com/tkr41850-debug/mcp-chain/internal/store"
    )

    // StatusCmd reports the status of a registered id.
    //
    // Exit codes (LOCKED — Phase 8 bash monitor depends on these):
    //   0  id resolved — stdout: "resolved\n"
    //   2  id pending  — stdout: "pending\n"
    //   1  unknown id or any other error — stderr: "mcp-chain: ...\n"
    //
    // The `if mcp-chain status $id; then ...` shell idiom works
    // intuitively: only a resolved id triggers the then-branch.
    type StatusCmd struct {
        ID string `arg:"" help:"Id to check."`
    }

    // Run wires statepath → store → runStatus and translates the
    // returned code into a process exit. Return-nil for code==0 so
    // kong's FatalIfErrorf sees success; os.Exit for 1/2 so the
    // shell observes the contract exit code without kong emitting
    // an extra "error:" prefix on stderr (Pitfall 2 / LD-4).
    func (c *StatusCmd) Run() error {
        path, err := statepath.Resolve()
        if err != nil {
            fmt.Fprintf(os.Stderr, "mcp-chain: %v\n", err)
            os.Exit(1)
        }
        code := runStatus(os.Stdout, os.Stderr, path, c.ID)
        if code != 0 {
            os.Exit(code)
        }
        return nil
    }

    // runStatus is the exit-code decision tree. Pure with respect to
    // the environment: callers pass in the state file path so tests
    // can use t.TempDir() without touching $XDG_STATE_HOME.
    //
    // Pre-condition: parent directory of `path` exists (statepath.Resolve
    // guarantees this in production; tests MkdirAll themselves).
    func runStatus(out, errW io.Writer, path, id string) int {
        st, err := store.Open(path)
        if err != nil {
            fmt.Fprintf(errW, "mcp-chain: %v\n", err)
            return 1
        }
        r, err := st.Get(id)
        switch {
        case err == nil && r.Status == "resolved":
            fmt.Fprintln(out, "resolved")
            return 0
        case err == nil && r.Status == "pending":
            fmt.Fprintln(out, "pending")
            return 2
        case errors.Is(err, store.ErrUnknownID):
            fmt.Fprintf(errW, "mcp-chain: unknown id: %s\n", id)
            return 1
        default:
            fmt.Fprintf(errW, "mcp-chain: %v\n", err)
            return 1
        }
    }
    ```

## STRIDE Threat Register

| Threat ID | Category           | Component                                       | Disposition | Mitigation Plan                                                                                                                                                         |
|-----------|--------------------|-------------------------------------------------|-------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| T-06-01   | Tampering          | `id` positional → `store.Get(id)` map lookup    | accept      | `store.Get` performs a pure `map[string]record` lookup (no shell, no SQL, no filesystem-path concatenation). Shell metachars / path-traversal / empty string all flow through to `ErrUnknownID`. No injection surface. [V5 partial per RESEARCH §Security Domain.] |
| T-06-02   | Information disclosure | `runStatus` stdout                           | mitigate    | `runStatus` writes ONLY the literal strings `"resolved\n"` or `"pending\n"`. Unit test `TestRunStatus_StdoutIsJustStatus` asserts byte-exact output so a future field leak would fail CI.                        |
| T-06-03   | Information disclosure | `runStatus` stderr on generic errors        | accept      | `fmt.Fprintf(errW, "mcp-chain: %v\n", err)` surfaces the wrapped `store` error. The store never embeds `OwnerToken` in its error messages (see `internal/store/errors.go` — sentinels only, no record data). Acceptable disclosure: file path in a corrupt-JSON error is operator-actionable, not sensitive. |
| T-06-04   | Denial of service  | 10-concurrent `status` timing test              | accept      | Bounded to N=10 by the test; production `mcp-chain status` is user-invoked one-at-a-time. | T-06-05   | Information disclosure | `--help` / bad-args / unknown-command output | mitigate    | `kong.Writers(os.Stderr, os.Stderr)` redirects to stderr so a script pipeline `mcp-chain status $id \| grep resolved` cannot false-positive on the Usage text (which contains the word "resolved" in the help description "Exits 0 resolved..."). Integration tests assert stdout is empty for all three cases. |
| T-06-06   | Elevation of privilege | `status` subcommand privilege model         | accept      | `status` is read-only and does NOT check `OwnerToken` — anyone with read access to state.json can observe the status of any id. This is intentional: Phase 8's bash monitor polls from a sibling shell session that does not share the `serve` process's OwnerToken. Parent-dir mode 0700 restricts filesystem access to the invoking user. |
