From 08-RESEARCH.md §Code Example #7 — verbatim `plugin/scripts/chain-wait.sh`. The file is ~140 lines; see the research doc for the complete source. Key structural landmarks:
```bash
#!/usr/bin/env bash
# chain-wait.sh — Poll mcp-chain status until resolved, error, or timeout.
# Exit codes: 0 resolved | 1 unknown id/error | 124 timeout
set -eu
BIN="${MCP_CHAIN_BIN:-mcp-chain}"
# ... arg parser (while + case; handles --timeout, --timeout=VAL, --help, positional <id>)
# ... duration parser (case "$DURATION" in *s|*m|*h) + [!0-9]* glob validation + 604800 clamp)
# ... invocation echo to stderr (LD-8)
START=$(date +%s)
while :; do
  set +e
  "$BIN" status "$ID" >/dev/null 2>&1
  CODE=$?
  set -e
  case "$CODE" in
    0) echo "continue"; exit 0 ;;
    2) ;; # pending — fall through to sleep
    *) # error — re-run to capture stderr, then exit 1
      ;;
  esac
  if [ "$BUDGET" -gt 0 ]; then
    NOW=$(date +%s); ELAPSED=$(( NOW - START ))
    [ "$ELAPSED" -ge "$BUDGET" ] && { echo "mcp-chain: timeout waiting for $ID after ${DURATION}" >&2; exit 124; }
  fi
  sleep 1
done
```

**LD-4:** `chain-wait.sh` shebang is `#!/usr/bin/env bash` but body uses ONLY bash 3.2-safe syntax: no `[[`, no `(( ))` as a command (OK inside `$(( ))`), no arrays, no `declare`/`local -n`, no `${var,,}`/`${var^^}`, no `mapfile`/`readarray`, no process substitution `<(...)`, no `&>`, no here-strings `<<<`. `set -eu` + `trap` permitted.

**LD-5:** Monitor exit-code translation: `mcp-chain status <id>` exit 0 → stdout `continue\n` + exit 0; exit 2 → `sleep 1` and loop; exit 1 (or anything non-0/2) → stderr error + exit 1.

**LD-7:** Timeout tracked via `START=$(date +%s)` + `NOW=$(date +%s)` + `ELAPSED=$(( NOW - START ))` in the poll loop. Expiry: stderr `mcp-chain: timeout waiting for <id> after <DURATION>` + exit 124 (matches `timeout(1)` convention). NO SIGALRM traps (resolved OQ-3).

**LD-8:** On invocation, `chain-wait.sh` prints one line to stderr BEFORE the first poll: `mcp-chain: waiting for <id>` (no timeout) OR `mcp-chain: waiting for <id> (timeout: <DURATION>)`. This is the HELPER-01 "echo on invocation" semantic.

**LD-9:** `chain-wait.sh` discovers the binary via `BIN="${MCP_CHAIN_BIN:-mcp-chain}"`. Env override for tests, `PATH` lookup in production. `plugin/commands/wait.md` instructs Claude to set `MCP_CHAIN_BIN="${CLAUDE_PLUGIN_ROOT}/bin/mcp-chain"` when invoking.

    // stripFrontmatter returns the body of a commands/*.md file with YAML
    // frontmatter (between --- markers) removed. Mirrors the awk logic in
    // scripts/check-prompt-wordcount.sh.
    func stripFrontmatter(raw string) string {
        lines := strings.Split(raw, "\n")
        n := 0
        var body []string
        for _, line := range lines {
            if line == "---" {
                n++
                continue
            }
            if n == 1 {
                continue // inside frontmatter
            }
            body = append(body, line)
        }
        return strings.Join(body, "\n")
    }

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `chain-wait.sh` duration parser (`--timeout $DUR`) | mitigate | Parse via POSIX `case "$dur" in *s\|*m\|*h) ... esac` + glob `[!0-9]*` rejects on the numeric-stripped portion + hard clamp `DUR_SEC > 604800` → exit 1 with `mcp-chain: bad duration`. No `eval`, no `$(( $dur ))` arithmetic expansion of user input (that would allow command injection via `$(rm -rf ~)`). LD-6 enumerates the allowed forms; anything else is rejected. |
| T-08-02 | Tampering | `chain-wait.sh` `$ID` positional → `"$BIN" status "$ID"` | mitigate | `$ID` is always double-quoted to prevent word splitting + glob expansion. `mcp-chain status` in Phase 6 treats its argument as an opaque lookup key (no shell, no `eval`), so even a maliciously-crafted id like `$(whoami)` would be passed literally to the binary and produce exit 1 (unknown id) — no command execution. The bashism lint + `bash -n` gate forbids `eval`/`exec $ID`/backticks in chain-wait.sh, closing the injection door at the script level. |
| T-08-03 | Tampering | `plugin/commands/wait.md` `$ARGUMENTS` → bash invocation | accept | Claude Code substitutes `$ARGUMENTS` verbatim into the prompt body. The prompt instructs Claude to invoke `bash "${CLAUDE_PLUGIN_ROOT}/scripts/chain-wait.sh" $ARGUMENTS` — unquoted `$ARGUMENTS` means Claude's rendered bash invocation word-splits per Claude's tool-call serialization. Because chain-wait.sh performs STRICT positional-arg parsing (exactly one positional `<id>`, exactly one optional `--timeout D`) and rejects unknown flags with exit 1, a malicious `$ARGUMENTS` like `x; rm -rf ~` would either be passed as two arguments (`x;` rejected as unknown flag, `rm` rejected as unknown, etc.) or consumed as one over-long `<id>` which the binary rejects as unknown. The attack surface is bounded by Claude's tool invocation model (the prompt is not an arbitrary-command template). Accept: the realistic attacker is a user pasting a bad timeout, not a remote code-injection vector. |
| T-08-04 | InformationDisclosure | `chain-wait.sh` stdout pollution | mitigate | stdout is a SIGNAL CHANNEL: `continue\n` on success is the ONLY token, consumed by Claude (or a pipeline). All diagnostics (invocation echo, timeout message, error passthrough) go to stderr. This is asserted by 08-VALIDATION.md Wave 2: `bash chain-wait.sh stub-pending | grep .` must be empty while polling (only stderr fires). Rationale: a future script pipeline of the form `chain-wait.sh $ID && <continuation>` relies on `continue` being the only resolve-path stdout; accidental stdout writes in the loop break that contract. |
| T-08-05 | Spoofing | `${CLAUDE_PLUGIN_ROOT}/bin/mcp-chain` binary substitution | accept | Claude Code controls the plugin cache directory (`~/.claude/plugins/cache/<hash>/`) and writes the binary there from the GitHub release artifact. A local attacker with write access to the user's cache directory could swap the binary. Out of mcp-chain's threat model — if an attacker has write access to `~/.claude/plugins/cache/`, they already have full user-account compromise. Phase 9 (release pipeline) adds GoReleaser checksum files; Phase 8 does not ship a binary. |
| T-08-06 | DenialOfService | chain-wait.sh unbounded poll loop | mitigate | LD-7 enforces `--timeout` with hard upper bound 168h (604800s). Without `--timeout`, the script waits forever — by design (HELPER-01 requirement). But: each iteration `sleep 1` then one `mcp-chain status` call (Phase 6 is a file-lock-guarded read, <5ms typical). No exponential backoff, no goroutine leak, no file-handle leak (each `status` invocation is a fresh subprocess). A user who invokes `chain-wait.sh $ID` with no timeout and an id that never resolves has explicitly requested indefinite wait — not a DoS, a feature. |
| T-08-07 | Tampering | `scripts/smoke-chain-wait.sh` `XDG_STATE_HOME` isolation | mitigate | The smoke harness creates `TMP=$(mktemp -d)` and exports `XDG_STATE_HOME="$TMP"`, scoping ALL state writes to the tempdir. `trap 'rm -rf "$TMP"' EXIT` cleans up even on test failure.
