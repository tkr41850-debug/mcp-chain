<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Process environment → `statepath.Resolve()` | `$XDG_STATE_HOME` and `$HOME` are read at runtime; both are user-controlled env vars (not network-attacker-controlled for a single-user local tool) |
| `statepath.Resolve()` → local filesystem | `os.MkdirAll(parent, 0o700)` materializes a directory on disk; path is derived from the above env vars |

Phase 3 has no network surface, no cryptographic surface, no external IPC. The only attack surface is "env var values influence filesystem writes" — mitigated by the `0o700` mode (owner-only access) and by the fact that `MkdirAll` refuses to create parents that would require elevated privilege. No `os/user` call means no NSS attack surface.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `$XDG_STATE_HOME` env var pointing at a user-writable but attacker-symlinked path (e.g., `$XDG_STATE_HOME=/tmp/attacker/link` where `/tmp/attacker/link` symlinks into a sensitive dir) | accept | Single-user local tool; same privilege level as the invoking user. `MkdirAll` follows symlinks per stdlib semantics; a user who sets hostile env vars against themselves is outside the threat model. Phase 4's file write at `0600` will still confine the content. Documented in RESEARCH.md Known Threat Patterns context (by reference). |
| T-03-02 | Information disclosure | Parent directory created with world-readable mode (e.g., `0o755`) leaking ID existence to other local users | mitigate | Hard-coded `0o700` in the `MkdirAll` call; tested by `TestResolve_XDGSet` and `TestResolve_HOMEFallback` asserting `Mode().Perm() == 0o700` on newly-created dirs. Note: pre-existing dirs with looser modes are preserved (see T-03-03). |
| T-03-03 | Information disclosure | User-created parent with looser mode (e.g., `0o755`) silently tightened by `Resolve()`, surprising the user | accept | Deliberate design: `MkdirAll` never chmods existing directories. Test `TestResolve_ParentAlreadyExists` pins this invariant. Rationale per RESEARCH.md Pattern 3 (lines 194–197): respecting user-chosen modes > surprising them. Security-relevant confinement is Phase 4's `0o600` file write, not the directory mode. |
| T-03-04 | Denial of service | `$XDG_STATE_HOME` pointing at a path on a full or read-only filesystem, or a path the user cannot write to | mitigate | `os.MkdirAll` returns an error wrapped with `fmt.Errorf("statepath: create parent dir %q: %w", parent, err)`; the quoted path makes the failure debuggable from stderr alone. `Resolve()` propagates the error instead of panicking — kong dispatch in `main()` prints it cleanly (per RESEARCH.md Standard Stack Alternatives row, lines 83–87). |
| T-03-05 | Elevation of privilege | NSS / `os/user.Current` invoking cgo or dlopen at startup, introducing attack surface (load a malicious NSS module, etc.) | mitigate | **Project-policy mitigation:** `Resolve()` uses `os.Getenv` directly. `os/user`, `os.UserHomeDir`, `os.UserConfigDir`, `os.UserCacheDir` are all banned on the startup path per CONTEXT.md line 32. `go list -deps ./internal/statepath/` smoke test (Task 1 verify + VALIDATION.md row 47) asserts `os/user` is NOT in the dep graph — any future drift breaks the build. |
| T-03-06 | Repudiation | User unable to determine which path `Resolve()` chose (XDG branch vs HOME fallback) | accept | Deferred to Phase 10's `--help` / README wiring per REQUIREMENTS.md CORE-06 second half ("Path documented in `--help` and README"). This phase's scope is resolution-only; the diagnostic surface lands in the CLI phase. Operator can always `strace` a running process or inspect `ls ~/.mcp-chain` / `ls $XDG_STATE_HOME/mcp-chain` to confirm. |

All mitigations are either code-path enforcement (Task 1's `0o700` literal, `os.Getenv`-only resolution) or dep-graph enforcement (Task 1 + Task 2 smoke verify that `os/user` is absent). No runtime defensive wrappers needed — `Resolve()` has a single-line happy path and a single-line error path.
